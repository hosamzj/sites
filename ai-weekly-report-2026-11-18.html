一、AI 智能体生态：协议层收束后，「协议之上还差四层」成为新共识

1. 协议走向稳定：A2A v1.1 RC 发布，AWS 给出跨组织参考架构

协议层的快速迭代期告一段落：A2A v1.0.1 稳定版（2026 年 5 月）后，v1.1 发布候选版已于 10 月 29 日打 tag，新增任务执行中的双向流式（two-way streaming）；A2A 此前已携 150+ 组织背书进入 Linux 基金会 Agentic AI Foundation（与 MCP 同屋檐）。AWS 于 11 月 12 日发布可落地的跨组织多智能体参考架构：LangChain 企业编排器与 Strands SaaS Agent 分处不同 AWS 账户，通过 A2A 通信、OAuth 2.0/OIDC 双向认证、全程无共享密钥——SaaS Agent 通过 Agent Card 只暴露一个精选技能而非内部工具清单，MCP 仍作为 Agent 内部协议。对企业的含义：跨公司 Agent 协作的「安全样板」已经存在，集成商与供应商之间的 Agent 对接可以直接引用这套模式。（来源：The Colony 基础设施周报（2026-11-16）、The Colony 协议审计（2026-11-16））

2. InfoWorld 泼冷水：仅靠 MCP + A2A 撑不起企业级规模

InfoWorld 11 月 11 日的分析在本周被大量转载：两家协议只解决「连接」，企业真正要补的是其上四层——身份与授权、业务上下文治理、业务流程再造、AgenticOps（智能体运维）。文中引用的两个数字值得记住：Gartner 预测 Fortune 500 企业平均两年内运行 15 万个以上 AI Agent；Collibra《2026 Hallucination Tax Report》显示 76% 企业在试点转生产时撞上关键障碍。同时独立爬虫对 A2A 生态的实测泼了第二盆冷水：Tranco 百万域名中仅发现 276 个 Agent Card、且无签名、无一个位于前 1,000 域名——「宣布支持」与「真实部署」之间仍有数量级差距。采购智能体平台时，「协议兼容性」是门票而非能力证明，评标仍应落到身份、治理与运维三件套上。（来源：InfoWorld via AI News（2026-11-11）、The Colony 协议审计）

3. 芯片设计数据接入 MCP：IC Manage GDP-AI 服务器上线

半导体设计数据管理商 IC Manage 于 11 月 17 日发布其 GDP-AI 系统的 MCP Server，让任意 AI Agent 直接查询设计、IP 与硅生命周期数据。这是「垂直行业数据源 + MCP 标准化接口」的又一个样本——对汽车电子研发有参照意义：PLM / 设计数据的 Agent 化访问，大概率也会以 MCP Server 形式出现，数据权限与审计设计要提前跟上。（来源：GlobeNewswire（2026-11-17））

4. 治理层持续加高：IndyKite「意图级访问控制」、Sierra 个人 Agent 协议

  • IndyKite AgentControl 发布 Intent-Based Access Control（IBAC，11 月 17 日）：把用户请求转成结构化「意图」，以签名令牌在多智能体链路中逐级传递，每跳只能收窄不能放大权限，跨 A2A / MCP 通用——最小权限原则从「账户级」细化到「任务级」。
  • Sierra 发布 Personal Agent Protocol 1.0（代号 Poppy，11 月 13 日）：定义「个人 AI Agent 如何对接一家企业」的标准入口（网站、API 或企业自有 Agent）——C2B 方向的协议空白开始被填补。
  • StudioX AI 支持气隙网络的 A2A 互通（11 月 15 日）：隔离内网中不同平台 Agent 可互派任务，对军工/机密产线类场景有参考价值。

（来源：EIN Presswire / IndyKite（2026-11-17）、dev.to 协议图谱（截至 2026-11-15））

对 IT 负责人的意义：协议之争已结束，接下来两年的工程主线是「协议之上的四层」。本周可做：① 把身份与授权（Agent ID、任务级意图令牌）、上下文治理、流程再造、AgenticOps 写成平台选型的四个独立评分维度；② 对供应商宣称的「A2A / MCP 支持」要求出示真实 Agent Card / 生产部署证据；③ 关注 Poppy 这类 C2B 协议——未来客户与供应商的 Agent 会直接找上门。

二、Microsoft Ignite 2026：Copilot 被重写——Autopilot、Workspaces 与 Agent 365 全家桶

11 月 17 日开幕的 Microsoft Ignite 2026 是 Copilot 史上最大一次产品重构。一句话概括：Copilot 从「办公助手」变成「人与 Agent 共同工作的环境」，同时微软把 Agent 治理（Agent 365）做成了独立平台。以下按「新体验 / Agent 365 治理 / 生态连接 / 开发侧」四组梳理。

1. 新 Copilot 体验：五个名字要记住

  • Home 与 Office in Copilot 正式 GA：Home 是 Chat + Cowork 的统一入口；Word、Excel、PowerPoint 完整嵌入 Copilot，在对话中直接创建和协作文件——Office 的边界正在溶解进 Copilot。
  • Autopilot 开始向 Frontier 客户推送：常驻（always-on）、主动（proactive）的个人智能体，拥有自己的身份、记忆和工具，在 Teams、Outlook、聊天、频道和文档中出现，可以像 @同事 一样被 @；它能盯频道、跟邮件、跑周期性工作、管理项目——官方演示的场景是独立完成整套供应商评审流程：排期、回溯计划、会前准备、会议纪要、跟进相关方。
  • Copilot Workspaces：团队 + 工作 + Copilot 的共享空间；个人 Autopilot 即将可带入 Workspaces，人类成员的角色从「干活」转向「指挥」。
  • Copilot Code：数周内 GA；Copilot Managed Runtime（安全托管自建应用）现已 GA。
  • Today（私人预览）：Outlook 与 Copilot 应用内的每日简报 + 全天动态刷新（Today Brief / Today Feed），帮员工盯住优先级。

2. Agent 365：治理平台正式成型，且直接管到「本地 Agent」

  • Entra Agent ID 扩展到本地 Agent：Microsoft Defender 与 Entra Global Secure Access 已能自动发现 60 多种本地 AI Agent（含 Claude Code、GitHub Copilot CLI）及其配置的 MCP 服务器，并自动分配身份——员工在终端上自装的 Agent 从此进入 IT 视野，可区分人机行为并施加访问控制。
  • Agent 365 Cost Management：在 M365 管理中心统一管控 Cowork、Copilot Studio、Managed Runtime、Dynamics 365 agents 等按量计费服务——支持 spend 策略、限额、告警与部门级 chargeback（成本分摊）；Frontier 本月追加支出预测与优化建议。FinOps for AI 首次有了开箱即用的落地形态。
  • Agent 365 Business Analytics（Frontier 预览）：把 AI 花费、采纳率与业务结果（任务成功率、节省工时）放在同一视图——回答「AI 到底值多少钱」。
  • 插件 / 技能访问控制 GA：管理员可按用户/组分配 Copilot 与 Cowork 中可用的插件和技能；MCP 服务器治理扩展到 Azure AI Gateway 及 LiteLLM 等第三方网关，封禁前可查看依赖关系避免误伤。
  • Action Center（12 月私有预览）：识别无人认领/闲置 Agent；Agent Map（预览）：发现功能重复的 Agent；Agent 活动可导出至 Azure Monitor / Application Insights。
  • Agent Accounts 12 月公共预览：Agent 获得持久身份 + 记忆 + 触发器，成为业务流程中的常驻角色。

3. 生态连接：Salesforce 进 Copilot，Dynamics 365 双向打通

Salesforce in Copilot 插件进入预览：38+ 预置销售技能，通过经认证的 Salesforce MCP 访问，在 Salesforce 既有权限内操作——跨 CRM 协作不再需要迁移数据。Dynamics 365 in Copilot 同步发布：业务数据与 Work IQ 原生融合，自然语言更新客户记录、准备日记账分录，且继承既有权限与治理。再加上上周 GA 的 Connector 写操作，「Copilot 作为统一工作入口、业务系统各自为后端」的架构已经清晰。（来源：Microsoft 官方新闻（2026-11-17）、Ignite 2026 Book of News、Microsoft Copilot 博客（2026-11-17）、Dynamics 365 博客（2026-11-17）、Agent 365 官方博客（2026-11-17））

4. 开发侧：微软自有模型与 Copilot 发行说明 11/17 批次

  • MAI Code 2 与 MAI Code 2 Flash 发布（11 月 17 日）：微软自研编码模型家族换代，叠加 Copilot Code，「用 Copilot 造 Copilot 应用」的闭环完整。
  • Skills in Microsoft 365 Copilot Chat 正式 GA：可复用的任务指令（含资源与脚本）直接在 Chat 中使用与分发，无需构建声明式 Agent。
  • 11/17 发行说明要点：Confluence Cloud 连接器支持 CQL 过滤（精确控制索引入口）；新增 Tableau 连接器（Copilot 直接解读 BI 看板）；Outlook 内可直接调用 custom engine agents；Copilot Studio 工作流新增 Agent Node（单步内完成推理 + 工具调用 + 响应）；Teams 上线 Express Voice Enrollment（语音档案用于发言人识别与会议洞察）。（来源：Microsoft Learn 发行说明（2026-11-17）、开发者更新、BenchLM 模型追踪）
行动清单（本周可启动）：① 申请 Frontier / 预览渠道，制定 Autopilot、Workspaces、Code 的试点名单（建议从供应链/采购部门开始——官方供应商评审演示与零部件企业高度相关）；② 在 Agent 365 中开启本地 Agent 发现，摸清员工已在使用哪些 CLI Agent 与 MCP Server——这是影子 IT 的「最后盲区」；③ 用 Agent 365 Cost Management 的部门 chargeback 功能设计 2027 年 AI 预算分摊模型；④ 关注 Copilot Chat fair use 限流（>2,000 席位组织 11/9 已生效）首周的 helpdesk 反馈，继续用 Agents usage report 量化许可缺口。

三、汽车与零部件：丰田万亿日元机器人计划与「连接性优先」投资次序

1. 本周最大行业新闻：丰田 + 供应商每年 1 万亿日元、40 万台机器人

Just Auto 11 月 13 日报道：丰田与其供应商体系计划自 2028 年起每年投入约 1 万亿日元（约 63 亿美元）更换老旧生产设备，在集团内外部署约 40 万台机器人（丰田集团工厂约 15 万台、供应商工厂约 25 万台）。路线图还包括：Arene 软件平台 2030 年扩展至 50 款车型、1,000 万辆（并可能向联盟伙伴开放）；2028 年落地 L2++ 端到端智驾；年内推出搭载全固态电池的车型；工厂设备、物流与供应链通过统一的 Factory Control Platform 连接。三阶段路径明确：常规机器人做重复工序 → 端到端产线物流同步 → 人机并肩协作；长期目标是把机器人技术对外销售，变成独立业务线。11 月 17 日，丰田通商与电装宣布组建新的车载软件单元，与路线图呼应。（来源：Pivot News / Just Auto（2026-11-14）、Just Auto（2026-11-17）、Imagine.ai 丰田企业 AI 部署档案）

2. 丰田的「数字化底账」给出一个可对标基准

第三方调研机构 Imagine.ai 本周更新的丰田档案显示：丰田在北美已运行50 多个生产级 Agent（ToyotaGPT）；设备诊断 Agent GearPal 把机器人/产线故障诊断时间从 5–6 小时压缩到 2–3 分钟；日本 10 座整车/单元工厂的车间 AI 平台由一线员工自建质检与异常检测模型，年节省超过 1 万工时。这套「数据底座 + 轻量 Agent + 物理 AI」的组合路径，与上周 Autoliv / BorgWarner 的案例共同构成零部件企业可直接对标的三级台阶：先做数据连通，再上流程 Agent，最后评估物理自动化。（来源：Imagine.ai 丰田档案（2026-11 更新））

3. Capgemini：68% 车企与供应商已在用或试点 Agentic AI

Capgemini Research Institute 本周被广泛引用的报告显示：33% 的主机厂与供应商已在产品研发和工程流程中使用 Agentic AI，35% 处于试点阶段——合计近七成。AI 已从「创新项目」变成工程部门的常规工具，晚于这个节奏起步的企业将在人才竞争与开发周期上处于劣势。（来源：Foley Automotive Update 引用 Capgemini Research Institute）

4. WardsAuto：投资次序的共识是「连接性先于 AI」

WardsAuto 与 Manufacturing Dive 11 月 11 日的 State of Automotive Manufacturing 论坛上，制造技术协会技术高级副总裁 Ryan Kelly 的判断被普遍认同：「设备不互联，就根本谈不上用 AI」——连接性投资是价值最大的先行项；与会者预测未来几年汽车行业将出现供应链深度数字化、更多机器人与人机协作、预测性维护权重上升、发运环节 AI 自动化加速。同时也有坦率的提醒：下游供应商视工艺数据为「秘方」，不愿与主机厂共享——AI 需要的新数据协作方式（如安全 vault 托管敏感数据）是组织课题，不是技术课题。（来源：WardsAuto（2026-11-13））

5. 上期供应链警报进入确认期

Nexperia「完全超额认购」与意法半导体对成熟制程产能移转的公开警告持续发酵（Reuters / Automotive News 上周报道，本周被 ETAuto、Goldsea 等多方转载跟进），叠加 WardsAuto 论坛上「汽车供应链无法像其他行业那样快速换源」的判断——车规芯片、存储、PCB 的保障动作（双源认证、长协锁产能）应在本月内完成立项。（来源：Automotive News（2026-11-11）、ETAuto Tech Digest（2026-11-11））

给汽车零部件企业的启示：丰田 1 万亿日元/年把「物理 AI 进厂」从试点叙事变成资本开支事实，且明确把 25 万台机器人放在供应商工厂——主机厂体系的自动化升级将逐级传导到 Tier1/Tier2。建议：① 评估自身工厂网络在丰田/其他主机厂路线图中的位置，提前布局机器人接口与数据连通；② 复制 GearPal 式「设备诊断 Agent」——投入小、见效最快的制造业 Agent 入口；③ 按「连接性 → 流程 Agent → 物理自动化」三级台阶重排 2027 数字化预算，不要把物理 AI 排在数据底座之前。

四、大模型格局：GPT-6.2 截胡 Ignite 周，旗舰降价 20% 成行业惯例

1. OpenAI 抢在 Ignite 当天发布 GPT-6.2 系列（11 月 17 日）

OpenAI 于 Ignite 开幕日推出 GPT-6.2 Astra 与 GPT-6.2 Sol，全线进入 ChatGPT、Codex 与 API：Astra 为迄今最强旗舰，定价 $8 / 百万输入、$40 / 百万输出——比 GPT-6 Astra（$10 / $50）再降 20%；Sol 定位编码、Agent 与专业工作的均衡默认档。头部实验室已把「旗舰迭代」节奏压到 10 周以内，且在对手发布会当天抢头条成为新常态。（来源：BenchLM 模型发布追踪（2026-11-18 更新）、TLDL 模型发布指南（2026-11））

2. Google 补齐快档：Gemini 4 Hydrogen GA（11 月 12 日）

Gemini 4 家族完成「旗舰 + 快档」组合：Hydrogen 作为 3.8 Flash 的继任者，发布当日即在 Gemini API 全 tier（含免费层）、AI Studio、Search 与 Gemini App 全量 GA。加上 11 月 10 日 GA 的 Carbon（$2 / $10 限时价，11 月 30 日恢复 $4 / $20），Google 已覆盖「极致能力—均衡—高速」全谱系。（来源：The Durability Curve 发布追踪（更新至 2026-11-16））

连续两周，Anthropic 与 OpenAI 先后把旗舰价格砍掉 20%——旗舰 API 一年内已累计降价逾 50%，且「发布即全平台」（AWS / Azure / Google Cloud 同步上架）成为标配。对企业而言：锁定单一模型的理由越来越弱，「评测—路由—成本回看」闭环才是核心资产。建议赶在 11 月 30 日 Carbon 定价窗口关闭前，完成与 Fable 5.2 / GPT-6.2 Astra 的同题评测，并把路由策略写进 2027 年 AI 平台规划。（来源：Fortune（2026-11-09）、Convika 模型价格对比（2026-11-16））

五、总结与下周观察重点

核心结论

  • Copilot 完成「环境化」重构。Ignite 2026 上 Home、Office in Copilot、Managed Runtime GA，Autopilot 与 Code 开始推送——微软把 Copilot 从功能升级为工作场所，且演示场景（供应商评审）直指供应链协同。
