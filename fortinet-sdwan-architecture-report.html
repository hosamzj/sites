01. 什么是 SD-WAN？

SD-WAN（Software-Defined Wide Area Network，软件定义广域网）并不是某一种单一设备，而是一套通过网络控制器与策略编排，把底层物理链路（MPLS、宽带、4G/5G）与上层业务流量解耦的广域网架构。

从传统 WAN 到 SD-WAN 的演进

传统 WAN 通常采用“hub-and-spoke”星型结构：每个分支机构的流量都要先回传到总部数据中心或 Hub，再经过安全栈（防火墙、IPS、Web 代理）后访问互联网或 SaaS。这种模型在 MPLS 时代运行良好，但面临三个明显瓶颈：

  • 流量绕远：访问 Office 365、Zoom、SaaS 的流量要先回总部，体验差、带宽浪费。
  • 链路绑定：核心业务过度依赖昂贵的 MPLS，新增链路需要逐台配置路由与安全策略。
  • 安全堆叠复杂：分支往往同时存在路由器、防火墙、交换机、AP、WAN 优化器等多台设备，运维成本高。

SD-WAN 的核心思路是：在分支边缘用一台统一设备（如 FortiGate）同时承担 NGFW、路由、SD-WAN 控制器、LAN 接入控制器等角色，通过策略定义“哪些应用走哪条链路”，并基于实时链路质量（延迟、抖动、丢包）动态切换。

SD-WAN 的四个核心能力：链路聚合与多路径传输、应用识别与智能选路、集中策略编排、原生安全集成（NGFW + IPS + SSL 检测）。

02. 为什么需要 Secure SD-WAN？

Fortinet 将其方案称为 Secure SD-WAN，强调 SD-WAN 不能只是“选路工具”，必须把安全内建到同一平台，避免为追求灵活性而引入新的攻击面。

🚀

数字化体验

SaaS、云应用、视频会议成为生产工具，要求分支到云的流量路径更短、更稳定。

💰

降低 WAN 成本

用宽带、4G/5G 替代或补充 MPLS，实现混合链路，降低每兆带宽成本。

🛡️

安全内建

分支直接访问互联网（DIA）必须同时做 IPS、Web 过滤、DNS 过滤、反病毒，而不是把安全全部交给总部。

🔧

简化运维

通过 FortiManager 统一模板、零接触部署（ZTP），实现数百个分支的快速上线。

03. Fortinet Secure SD-WAN 核心组件

Fortinet 的方案把 SD-WAN 建立在 FortiOS 操作系统之上（最新为 FortiOS 7.6），核心平台是 FortiGate；再围绕 FortiManager、FortiAnalyzer、FortiSwitch、FortiAP、FortiExtender、FortiAI 与 FortiAIOps 等组件形成完整的分支到云端架构。

组件全景

FortiGate

既是 NGFW，也是 SD-WAN 边缘控制器。FortiOS 内置 SD-WAN 功能，支持应用识别、多链路负载、IPSec/ADVPN 叠加网、身份策略、流量整形等。

FortiManager

集中管理与编排控制台。可以批量下发设备配置、SD-WAN 模板、策略包、零接触部署（ZTP）配置，并与 FortiAnalyzer 集成在同一界面。

FortiAnalyzer

日志聚合与分析平台，把安全事件、SD-WAN 流量、链路质量、应用性能等数据转化为可视化报告，支持自动报表。

FortiSwitch / FortiAP

通过 FortiLink 技术，FortiGate 可直接作为 LAN 交换机与无线 AP 的控制器，实现“安全即端口”——每个端口/SSID 都继承防火墙策略。

FortiExtender

4G/5G 无线 WAN 扩展模块，作为主链路故障时的备用链路，或作为临时站点快速上线。

FortiGuard / FortiSandbox

威胁情报、应用签名、AI 驱动的恶意软件分析，持续更新到 FortiGate，确保应用识别与安全策略始终最新。

FortiAI / FortiAI-Assist

FortiOS 7.6 将生成式 AI 能力深度集成到 FortiManager 与 FortiAnalyzer，支持自然语言查询、配置辅助、故障排查与文档检索，帮助 IT 团队编排和自动化整个 Secure SD-WAN 基础设施。

FortiAIOps

基于 AI/ML 的 IT 运维平台，采集 FortiGate、FortiSwitch、FortiAP、SD-WAN、FortiExtender 的数据，实现异常检测、事件关联、预测性分析与根因定位，降低 NOC 工单量。

Digital Experience Monitoring (DEM)

内置数字体验监控，从终端、ISP、SD-WAN 链路到 SaaS/私有应用，统一关联用户体验与网络性能，实现实时问题定位。

FortiGate 作为统一边缘平台

Fortinet 的架构思路是“设备整合（Edge Consolidation）”。FortiGate 不再是单纯的防火墙，而是：

  • SD-WAN 路径控制器
  • 应用识别引擎（含加密流量识别）
  • NGFW / IPS / 反病毒 / Web 过滤
  • 路由与交换控制器（FortiLink）
  • 零接触部署代理

这意味着分支机构可以用一台 FortiGate 替代传统路由器、独立防火墙、WAN 优化器、交换机控制器、无线控制器等多个设备，显著降低 CapEx 和 OpEx。

05. 典型架构设计模式

Fortinet 官方文档《SD-WAN Architecture for Enterprise》总结了多种常见设计模式。企业应根据数据中心数量、云采用程度、合规要求与分支规模进行组合。

模式一：单数据中心 + 分支混合链路（Hub-and-Spoke）

最经典的企业 WAN 模式：总部/数据中心作为 Hub，分支机构通过 MPLS + 宽带两条链路接入。FortiGate 在分支创建 SD-WAN 虚拟接口，包含 MPLS 成员与 IPSec 宽带成员；总部同样配置双 Hub 或 Active-Passive 网关。

  • 内部业务流量优先走 MPLS，互联网/SaaS 流量走本地宽带直出（DIA）。
  • 当 MPLS 故障时，关键应用自动切换到 IPSec 隧道；同时通过 SLA 探测实时评估链路质量。

模式二：双数据中心主备网关

企业有两个数据中心或区域总部时，可配置 Primary/Secondary 网关。每个分支的 SD-WAN 规则同时指向两个 Hub，并根据延迟、丢包等 SLA 指标选择最佳 Hub。该模式适合跨地域业务、灾备要求高的场景。

模式三：Direct Internet Access（DIA）本地互联网直出

SaaS 流量（Microsoft 365、Salesforce、Zoom、Teams）不再回传总部，而是直接在分支通过宽带链路安全出网。FortiGate 的本地 NGFW 能力确保分支 DIA 不会成为安全短板。

模式四：Cloud On-Ramp 多云接入

在 AWS/Azure/GCP/阿里云等部署 FortiGate-VM 作为 Cloud Gateway，与总部和分支建立 IPSec 或 ADVPN 隧道。分支访问云应用的流量可以就近进入云网关，避免“云到数据中心再绕回云”的迂回路。

模式五：SD-Branch（安全分支）

把 LAN 也纳入统一安全管理：FortiGate 通过 FortiLink 管理 FortiSwitch 和 FortiAP，SSID 与交换机端口直接映射为防火墙接口。这样每个端口、每个无线 VLAN 都可以执行 NGFW 策略、网络分段、NAC 与访客隔离。

模式六：SD-WAN Overlay-as-a-Service（OaaS）

对于不想自建和维护 Hub 基础设施的企业，FortiGate Cloud Advanced 提供 SaaS 化的 SD-WAN 叠加网服务。Fortinet 托管地理冗余的 Hub，企业通过点击式界面配置分支互联与策略，显著降低部署门槛与运维成本。

模式七：Unified SASE 混合部署

在已有 FortiGate SD-WAN 的基础上，通过 FortiSASE 将安全能力平滑延伸到云端 PoP 与远程用户。同一策略引擎同时管理分支 SD-WAN 规则与云端 SSE 规则，实现“本地直连 SaaS + 云端安全栈”的混合架构，避免推倒重来。

“FortiGate is the platform for that. FortiOS is the underlying operating system … but it's much more than just WAN path control, application awareness and application steering. We're really talking about Secure SD-WAN, including identity-based policy and edge consolidation.”
— Fortinet SD-WAN Architecture & Demo, Tech Field Day

06. 配置逻辑与关键概念

理解 FortiOS 中的 SD-WAN 配置对象是落地的前提。核心对象包括：SD-WAN 成员（Member）、SD-WAN 区域（Zone）、SD-WAN 规则（Rule）与性能 SLA（Performance SLA）。

核心对象

SD-WAN 成员（Member）

可以是物理接口、VLAN 接口、聚合接口、IPSec/GRE/IPIP 隧道，甚至 FortiExtender 蜂窝接口。每个成员代表一条可用的 WAN 路径，需要配置网关、成本、带宽上下行。

SD-WAN 区域（Zone）

一组 SD-WAN 成员的逻辑集合。最常见的是把“物理 WAN 接口”放入一个 Zone，把“IPSec 隧道/Overlay”放入另一个 Zone。规则可以按 Zone 指定选路范围。

SD-WAN 规则（Rule）

基于源/目的地址、应用、用户、服务、DSCP 等条件匹配流量，并指定策略动作：最优链路、负载均衡、溢出（Spillover）、强制某条链路、优先级排序等。

性能 SLA（Performance SLA）

周期性探测目标服务器（如 DNS、ICMP、HTTP、FortiGuard 服务器），衡量延迟、抖动、丢包。SLA 结果触发链路切换或静态路由更新。FortiOS 支持被动探测（利用真实流量）与主动探测两种模式。

静态路由与接口

默认路由指向 SD-WAN 虚拟接口（virtual-wan-link），而不是单条物理链路。防火墙策略必须允许流量通过 SD-WAN 接口。

Underlay 与 Overlay

Underlay（底层网络）是物理链路本身：MPLS、宽带、4G/5G。它们负责点到点的 IP 可达。Overlay（叠加网络）是跑在 Underlay 之上的逻辑隧道，通常用 IPSec 或 ADVPN 建立，把不同分支与数据中心/云网关组成一张加密、可路由、策略统一的虚拟网络。

Fortinet 的 ADVPN（Auto-Discovery VPN）是一种优化型全互联方案：分支之间默认通过 Hub 学习路由，当需要直接通信时动态建立按需隧道，解决传统 Full-Mesh 隧道数量爆炸的问题。

应用识别（Application Awareness）

FortiGate 的 SD-WAN 选路可以精确到应用级别。例如：

  • 语音/视频（Zoom、Teams、SIP）优先选择低延迟、低抖动链路。
  • ERP/OA 流量优先走 MPLS 或总部 IPSec 隧道。
  • 云存储备份可以走低成本宽带，并设置带宽限制。
  • 未知或高风险流量强制经过 IPS、Web 过滤、沙箱检测。

FortiGuard 应用签名库持续更新，对加密流量也能通过 SNI 或深度识别技术进行判断。

07. 部署与 AI 辅助运维实践

从 5 分钟快速配置到数千分支的零接触部署，Fortinet 提供了从手工到自动化的完整部署路径。关键是把基础配置（接口、路由、SLA、规则）抽象为模板，再通过 FortiManager 批量推送。FortiOS 7.6 进一步引入 FortiAI 与 FortiAIOps，让部署后的运维从被动告警转向预测性、AI 辅助的主动管理。

5 分钟快速配置（单台 FortiGate）

以“Setup SD-WAN in Under 5 Minutes”视频中的配置为例，单台 FortiGate 上 SD-WAN 的最小配置步骤为：

  1. 确认 WAN 接口已配置 IP 与网关。
  2. 在 Network → SD-WAN 中创建 SD-WAN 成员，把各 WAN 接口加入虚拟 SD-WAN 接口。
  3. 添加默认静态路由，目标 0.0.0.0/0 指向 virtual-wan-link。
  4. 确保防火墙策略允许内网到 virtual-wan-link 的流量。
  5. 创建 Performance SLA，探测目标服务器并设置延迟/抖动/丢包阈值。
  6. 创建 SD-WAN 规则，按应用或目的地址指定选路策略（如 Spillover、Best Quality、Manual 等）。

零接触部署（ZTP）与模板化

对于大量分支，手工逐台配置不现实。FortiManager 提供：

  • Device Manager：统一纳管所有 FortiGate，支持按模型/地区/角色分组。
  • Provisioning Templates：预定义系统设置、接口、管理员、DNS、NTP 等。
  • Policy Packages：统一的防火墙策略、SD-WAN 模板、VPN 配置。
  • SD-WAN Overlay Wizard：四步向导即可创建双 Hub 或 Full-Mesh（ADVPN）叠加网，自动生成 IPSec 隧道、BGP/OSPF 路由、SD-WAN 区域与规则。
  • Zero Touch Provisioning：新设备接入互联网后自动联系 FortiManager 或 FortiDeploy，拉取配置文件并上线。

运维监控

FortiManager 提供拓扑视图、SD-WAN 链路性能、应用流量分布、设备健康度等仪表盘；FortiAnalyzer 则提供安全事件、日志审计、合规报表。两者集成后，管理员可以在一个界面中完成“网络 + 安全”的统一运维。

FortiAI 与 FortiAIOps 辅助运维

部署上线只是第一步，持续运维才是价值兑现的关键。FortiOS 7.6 通过 AI 能力降低运维复杂度：

  • FortiAI-Assist：在 FortiManager 中通过自然语言询问配置、排错、监控指标，AI 会基于文档与实时数据给出建议。
  • FortiAIOps：自动学习 SD-WAN 链路与应用流量的基线，识别异常模式，预测潜在故障，并给出修复建议。
  • DEM + Underlay Monitoring：从终端到 SaaS 应用的全链路体验监控，让问题定位从“链路是否通”细化到“应用体验是否受影响”。

部署最佳实践：先在实验室用 2 台 FortiGate 跑通 Hub-Spoke + ADVPN；再抽取配置为 FortiManager 模板；最后在小批量分支试点验证 SLA 阈值与选路策略，确认无误后再批量推广。上线后开启 FortiAIOps 与 DEM，持续收集基线数据，为 AI 辅助优化提供依据。

08. 授权模式与行业认可

理解 Fortinet 的采购与授权模式，有助于企业在规划 SD-WAN 时避免预算与合规风险。Fortinet 近年来持续将 SD-WAN 与其安全服务深度绑定，并通过行业分析师报告验证其市场地位。

SD-WAN 不再额外收费

Fortinet 的核心策略是“安全驱动网络（Security-Driven Networking）”：SD-WAN 功能作为 FortiOS 的内置模块，在所有 FortiGate 型号上均可免费启用，无需为 SD-WAN 本身支付单独的带宽许可或按流量计费。企业真正需要采购的是：

  • FortiGate 硬件或虚拟机：按性能与接口形态选型。
  • FortiCare 支持服务：硬件保修、固件更新、技术支持。
  • FortiGuard 安全服务包：应用控制、IPS、Web 过滤、DNS 过滤、反病毒、沙箱、威胁情报等；SD-WAN 所需的应用识别与 SLA 监控也依赖这些服务包。
  • FortiManager / FortiAnalyzer / FortiCloud：集中管理、日志分析、云服务按需订阅。

采购模式变化：截至 2026 年 1 月，Fortinet 不再单独销售 SD-WAN、SASE、Attack Surface 等独立 SKU，而是统一通过 FortiGuard AI 驱动的安全服务包进行采购。这意味着新签单必须把 SD-WAN 放在整体安全与网络架构中评估，而不是单独谈判一个 SD-WAN 模块。

09. FortiOS 7.6 与 Unified SASE 新能力

FortiOS 7.6 是 Fortinet 最新一代操作系统，将 SD-WAN 从独立的广域网优化工具，升级为统一安全访问服务边缘（Unified SASE）的核心底座。关键变化在于：网络、安全、AI 运维、零信任访问共享同一操作系统、同一策略引擎、同一数据模型。

Fortinet Unified SASE：SD-WAN + SSE 融合

传统 SASE 市场把 SD-WAN 与 SSE（安全服务边缘，包括 SWG、CASB、ZTNA、FWaaS）拆分成不同供应商或不同控制台。Fortinet 的策略是：

  • 同一 OS（FortiOS）：分支 FortiGate 跑 SD-WAN，云端 / PoP 跑 FortiSASE，策略一致。
  • 同一控制台（FortiManager）：统一编排 SD-WAN overlay、SSE 安全策略、ZTNA 访问规则。
  • 同一数据模型：SD-WAN、SSE、端点、零信任共享遥测、DEM 数据与日志。
  • 灵活部署：既可保留现有 FortiGate 硬件，也可通过 FortiSASE 云服务按需扩展，无需推倒重来。

对企业而言，这降低了“SD-WAN 改造后还要再上一轮 SASE”的重复投资，也避免了多个供应商之间的策略碎片。

FortiAI 与 FortiAI-Assist

Fortinet 将原先的 Fortinet Advisor 统一更名为 FortiAI，并在 FortiOS 7.6 中深度集成到 FortiManager 与 FortiAnalyzer：

  • 自然语言查询：IT 人员可用对话方式询问配置、监控、故障、文档。
  • 配置辅助与自动化：AI 协助生成策略、验证部署、推荐优化。
  • 事件研判：结合 FortiAnalyzer 数据湖，快速定位 SD-WAN 链路或安全事件根因。

FortiAIOps for SD-WAN

FortiAIOps 是面向 Fortinet 网络的 AI/ML 运维平台。在 SD-WAN 场景中，它提供：

  • SD-WAN 接口健康、SLA 趋势、应用流量的可视化与异常检测。
  • 基于历史数据预测链路退化，提前触发策略调整。
  • 将 WLAN、LAN、SD-WAN、LTE/5G 网关的告警统一关联，减少误报和工单量。

Underlay & Application Monitoring Service

这是 FortiOS 7.6 在 SD-WAN 监控层面的重要增强。通过 FortiManager 与 FortiGuard Labs 的 SaaS/云应用数据库，它可以：

  • 监控 ISP 链路、路径、应用三层性能。
  • 基于真实应用体验（而不仅是链路通断）做智能选路。
  • 让 IT 团队优先处理影响关键业务的网络问题，而不是被大量链路告警淹没。

Overlay-as-a-Service

FortiGate Cloud Advanced 提供 SD-WAN Overlay-as-a-Service：企业无需自建 Hub 或管理复杂的 IPSec/BGP 配置，即可通过 SaaS 化控制台快速建立分支互联。特点包括：

  • Fortinet 托管的地理冗余 Hub。
  • 点击式策略配置，降低技术门槛。
  • 减少自建 Hub 的硬件、机房、运维成本。

Universal ZTNA 与分布式执行

FortiOS 7.6 将零信任网络访问（ZTNA）内建到 SD-WAN 平台中：

  • 基于用户身份、设备 posture、应用风险，动态决定是否允许访问。
  • 每 60 秒进行一次 posture 检查，持续验证而非一次性认证。
  • 支持 50+ 端点属性，实现精细化访问控制。
  • 流量在最合适的边缘（分支、云端、PoP）解密与检测，避免“ hair-pinning”绕回数据中心。

总结 7.6 核心升级：从“SD-WAN 是选路工具”升级为“SD-WAN 是统一安全网络底座”，整合了 AI 辅助运维、SSE/SASE、ZTNA、DEM、Overlay-as-a-Service 与 ASIC 加速的分布式安全执行。

10. 汽车 / 制造业应用启示

对于汽车与零部件制造行业，SD-WAN 不仅是网络优化工具，更是支撑工厂数字化、供应链协同、远程办公与全球研发协作的关键基础设施。

🏭

工厂与产线互联

总部、区域工厂、物流中心、研发中心通过混合链路互联，MES/ERP/PLM 流量走稳定 MPLS/IPSec，普通办公流量走本地宽带。

🤖

IoT 与 OT 安全分段

FortiGate + FortiSwitch 通过 FortiLink 把产线 PLC、AGV、质检设备划入独立 VLAN，并执行 NGFW 策略，避免 IoT 威胁横向移动。

☁️

云研发与 PLM 上云

全球研发团队访问公有云上的 PLM、CAD、仿真平台时，通过 Cloud On-Ramp 就近接入，降低跨国链路延迟。

🚗

供应链与经销商网络

供应商、经销商、4S 门店数量多且分散，可用 FortiGate 40F/60F 桌面型设备 + ZTP 快速上线，统一安全策略。

OT 环境：FortiGate Rugged 60F 加固方案

汽车制造工厂的产线、仓库、室外堆场、变电站等 OT 环境，对网络设备有特殊要求：宽温、抗振动、抗电磁干扰、DIN 导轨安装、直流供电等。Fortinet 推出了首款面向 OT 环境的 SD-WAN 设备 FortiGate Rugged 60F：

  • 通过 IEC 61850-3 与 IEEE 1613 认证，适用于电力、工业控制场景。
  • 在紧凑机身内集成 SD-WAN、高级路由、NGFW 三大能力。
  • 支持 DIN 导轨或标准机架安装，内置 LTE 可选。
  • 能在极端温度、湿度、振动、EMI 环境下稳定运行。

典型案例：Sullair Argentina 在关键基础设施资产网络中部署 Fortinet Secure SD-WAN，实现了 OT 环境的可靠互联与安全防护。汽车企业可参考此模式，将 Rugged 60F 用于冲压、焊装、涂装、总装等产线边缘或远程仓库。

与 AI/Copilot 的协同

随着 Microsoft 365 Copilot 等 AI 助手在汽车企业落地，员工对 Teams、SharePoint、OneDrive 的访问体验直接影响生产力。SD-WAN 可以基于应用识别把 Copilot 相关流量优先调度到质量最好的链路，并通过 DIA 本地出网，避免回传总部带来的延迟。FortiOS 7.6 的 DEM 功能还能持续监控这些 AI 应用的终端体验，帮助 IT 在问题影响业务前主动修复。

12. 总结与建议

Fortinet Secure SD-WAN 的本质是把“网络连接”与“安全防御”合并到同一平台，让企业既能享受混合链路的成本优势，又不会因为分支本地出网而牺牲安全性。

给汽车/制造企业的落地建议：

  • 从痛点切入：优先改造视频会议体验差、SaaS 访问慢、MPLS 成本高的分支。
  • 统一平台：分支尽量用 FortiGate 统一承载 NGFW + SD-WAN + LAN 控制器，减少设备堆叠。
  • 先试点再推广：选择 2~3 个典型分支 + 1 个数据中心，跑通 Hub-Spoke + DIA + ADVPN 后再模板化。
  • 安全不放松：分支本地互联网直出必须启用 IPS、DNS 过滤、Web 过滤、反病毒，并接入 FortiAnalyzer 统一分析。
  • 为 AI 应用预留带宽：在 SD-WAN 规则中识别 Teams/SharePoint/Copilot 等应用，设置高优先级 SLA 策略。

随着汽车企业加速上云、全球化协作与智能制造，SD-WAN 将从“网络优化项目”升级为“数字基础设施底座”。Fortinet 的硬件平台 + 统一操作系统 + 集中管理编排，为这一转型提供了可扩展、可复制的落地路径。
